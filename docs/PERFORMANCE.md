# 性能与验证口径

位置更新由 Windows 顶层窗口事件触发。常规定时器用于状态补偿，注册事件失败时退回较快轮询；平移只更新坐标，尺寸或 DPI 改变时再布局。实际显示仍受 Windows 合成与系统负载影响。

侧栏位置扣除 DWM 报告的当前物理边框，不覆盖边框像素，也不缩放旧 DPI 缓存中的边框值。背景约每 2 秒做一次 HUD 范围的小区域屏幕拷贝，只使用四条 1 像素边缘，中间像素忽略；两侧保留原生像素列作为取样来源。拷贝缓冲按尺寸复用，典型 72×661 像素约占 0.18 MiB；不隐藏 HUD、不复制整个 Codex 窗口。采样先检查源像素属于目标窗口，遮挡或移动时跳过。通过四边颜色重建并缓存背景，只有尺寸或采样改变才重建，绘制直接复用位图；逐行写入像素避免完整画面的托管大对象分配。

统计每秒增量读取。会话索引和选择配置只在文件变化后解析；额度快照复用到重置边界；未变化读数跳过重绘，数字字体测量按文本、尺寸和 DPI 缓存。运行状态变化时至少间隔约 5 秒写盘，稳定时约 30 秒写一次。

两条日志读取链路共用文件身份与游标实现。无变化时不重新读取日志内容；追加时除新增字节外，仅检查头部和游标前各至多 256 字节的内容检查点，并更新检查点。额度的所有游标继续在同一读取锁下共用一个 8 KiB I/O 缓冲；会话各自保留半行，大行处理完成后回收扩大的行缓冲。文件替换或改写引起的重读属于恢复成本，不计作普通小追加路径。

1.0.2 将正文和读数分别作为统一字号的分组，使用粗体，基准字号分别为 8.5 pt 和 11 pt，时间与容量读数不再使用额外字号。目标像素字号只按栏宽和 DPI 形成，再根据真实标签尺寸共同拟合，不先随窗口高度压缩字体。仅可见项目参与，长读数不会独自缩小，隐藏项目不会压低其他读数的字号。策略和缓存集中在 `Typography.cs`；缓存文本、尺寸、基准字号、DPI 与字体状态，不变时不重新测量或更新字体。极小高度仍保留按实际行高限制字号的紧凑布局。最终字号取决于当前内容和可用空间，并非固定屏幕像素。

账号额度另用文件系统变化通知，常规定时器约每 200 ms 检查变化；启动时读取近期日志末尾，之后仅在后台读取新增字节，更新额度标签，不提高 UI Automation 的会话识别频率。最多保留 128 个文件的游标，复用一个 8 KiB 读取缓冲；普通大段工具输出只检查前 1 KiB，额度候选行最多保留 64 KiB。文件截断、替换和半行写入单独处理。启动时按文件元数据选择最新 16 个日志，运行中不反复扫描全部历史；30 秒的近期目录检查用于补偿通知丢失。这个间隔不代表服务器额度快照产生频率。

轮次和压缩计数在同一遍增量读取中更新，不增加文件轮询或网络访问；只保存用于去重的事件 ID，不反序列化压缩记录里的整段替换历史。

名称测量只在文字、栏宽或 DPI 变化时进行，窗口平移复用结果。时间复用每秒的数据刷新；只有缩写时间变化时更新该标签，不因时钟变化重绘全部读数。当前布局不生成悬停提示。

HUD 已删除悬停提示控件、事件和说明生成代码；输入和输出各自显示最近请求与对话累计，模型默认隐藏。数字拟合复用标签列表。

## 四边背景与代码检查

2026-10-15 对相同的 72×661 像素区域做 200 次强制取样：

| 实现 | 平均墙钟耗时 | p95 | 200 次进程 CPU 时间 |
| --- | --- | --- | --- |
| 原两点取色 | 11.23 ms | 12.08 ms | 46.9 ms |
| 四次窄条屏幕拷贝 | 22.43 ms | 23.03 ms | 265.6 ms |
| 一次小区域拷贝，使用四边 | 5.54 ms | 6.34 ms | 93.8 ms |

墙钟耗时包含屏幕读取等待；实际周期约两秒，不能把上述值当作每帧开销。四次拷贝版本的 30.5 秒现场样本，整机平均 CPU 0.0213%，工作集 71.20–71.22 MiB，私有提交 49.54–49.57 MiB。现场样本包含实际会话及后台日志活动，与微基准的隐藏窗体不是同一口径。

优化后重启的 30.5 秒现场样本，整机平均 CPU 0.0213%，工作集 55.71–56.95 MiB，私有提交 35.56–36.40 MiB。当时 Codex 选中“首页”，没有当前会话读数；不能把它与之前的聊天活动状态直接比较，重启与会话缓存也会改变内存。相同区域取色微基准才是这次局部优化的对照依据。

本轮同时检查了窗口事件、日志读取、统计、绘制缓存、菜单、设置迁移和打包脚本。修复两处边界：UI 的额度变化查询不再等待后台文件读取锁；布局使用当前 DWM 物理边框，覆盖旧侧栏缓存。测试在 160 ms 的后台锁持有期间验证 UI 查询不阻塞，并用自己的隐藏窗口验证旧边框缓存不会覆盖现值。菜单重建统一释放旧项，取色缓冲与背景位图在 HUD 退出时释放。未发现遗留调试标记或旧悬停提示逻辑；旧设置迁移继续保留。

## 历史样本：布局合并前的 11 项数据与跨会话监听

2026-10-15，同一台 24 逻辑处理器电脑上：

- 优化前的 11 项运行副本，25.4 秒采样平均 CPU 为整机 0.0358%（单核等效 0.86%），工作集约 68 MiB，私有提交约 46–48 MiB。该样本保留实际会话和后台日志活动，不是纯空闲或恒定负载。
- 优化后的运行副本，预热 8 秒再采样 30.3 秒，平均 CPU 为整机 0.0279%（单核等效 0.67%），工作集 58.06–59.01 MiB，私有提交 42.58–43.58 MiB。两个现场样本的日志活动不同，重启也释放了历史缓存；不能把全部差值归因于优化，更不能据此断言长期不会增长。
- 相同隐藏窗体和输入、600 次无变化渲染，交替运行五轮取中位数：旧 7 项 12.93 ms，优化前 11 项 42.25 ms，优化后 11 项 19.73 ms。对应窗体初始工作集中位数为 37.50 / 39.29 / 39.08 MiB，私有提交为 28.64 / 28.98 / 29.02 MiB。隐藏窗体不包含实际 UIA 和会话解析，不能替代整个运行进程的内存读数。
- 64 次小日志追加：额度读取从 16,777,216 字节降为 20,288 字节，约减少 99.88%；gen0 回收从 32 次降为 0 次。读取量包含系统缓存，不代表物理磁盘实际读取量；文件打开等固定开销仍在，不能据此宣称整机 CPU 同比例下降。
- 预热后重建 80 次菜单并创建其原生句柄，GDI 资源 19 → 19，USER 资源 28 → 28，主题跟踪表保持 14 项。该隔离泄漏检查使用强制 GC，实际 HUD 不做强制 GC 或工作集裁剪。

可对运行副本做只读采样，报告保存在忽略的 `.local/`：

```powershell
.\scripts\measure-process.ps1 -ProcessId (Get-Process CodexLiteHud).Id -Seconds 30 -Report .local\process-sample.json
```

短采样只能说明对应时段的表现；会话大小、首次解析、切换、其他聊天更新和系统调度都会影响结果，不能替代长时间稳定性验证。

2026-10-15 的本机开发构建样本：

- 相同隐藏窗体、600 次未变化读数渲染，约 57 ms 降至 14 ms。这是局部渲染负载，不代表整体 CPU 同比例下降。
- 原生移动测试以自己的屏外测试窗口发出位置变化，事件跟随的 p95 通常约 2–3 ms。它不是对用户实际拖动的逐帧测量。
- 24 逻辑处理器机器上的一次约 8 秒轻负载采样，整机口径 CPU 约 0.05%，单核等效约 1.15%；工作集约 60 MiB，私有提交约 45–46 MiB。这些不是跨机器的资源上限，首次解析和切换大日志会波动。

保留 .NET/WinForms 和无障碍组件的基础占用。HUD 自身无联网和模型调用；会话中已经发生的 token 仅用于显示，不是 HUD 新增消耗。
