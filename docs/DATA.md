# 数据与统计

## 读取范围

`CODEX_HOME` 或默认 `%USERPROFILE%\.codex` 下：

- `session_index.jsonl`：会话 ID 与名称，按文件元数据变化缓存。
- `sessions/`、`archived_sessions/`：增量读取日志中的统计记录。
- 最新编号的 `state_*.sqlite`：使用 Windows `winsqlite3.dll` 只读查询 ID、归档状态及可用的 `title` / `name`，补全尚未进入索引的新对话并区分同名会话。当前数据库名称优先于旧索引；不支持标题字段的旧结构仍可读取 ID，数据库不可用时退回索引。按数据库和 WAL 的文件元数据变化刷新，未变化时缓存至多 5 秒；不读取数据库中的聊天正文。

当前窗口选中项来自 Windows UI Automation。只显示能够可靠对应到本机日志的聊天；多个未归档同名项仍需手动固定。

## HUD 自己的文件

`portable.flag` 存在时，保存到程序旁的 `data/`；否则保存到 `%LOCALAPPDATA%\CodexLiteHud`。`CODEX_LITE_HUD_DATA_HOME` 可以覆盖该路径。

- `position.json`：锁定状态、侧栏底部间距和解锁后的主窗口相对位置；兼容旧版仅保存底部间距的文件。
- `display.json`：显示项目、顺序和布局版本；首次运行仅隐藏模型。旧布局迁移为新默认顺序，独立“上次入/出”并入输入和输出；之后显式开启模型的选择会保存。
- `session.json`：自动/固定模式，以及固定会话的 ID。
- `status.json`：运行位置、目标窗口、最近读数和识别状态，可能包含会话名。

这些是运行数据，不进入源码或发行包。HUD 不读取 `auth.json`，不连接网络，不发送模型请求，不改写 Codex 的配置、会话和数据库。

## 读数边界

输入和输出各显示两行：“本次”为最近一次已记录模型请求，“对话”为本会话累计，不累计整轮中的多次请求。输入包含缓存，输出包含推理；上下文只取最近记录的单次请求输入加输出。HUD 与菜单的悬停提示已移除。`tok/s` 的分母包含等待，不能当作服务器纯解码速度。

账号额度按本地记录时间取较新快照。启动时只检查会话日志文件元数据，读取最近修改的至多 16 个日志的末尾 256 KiB；之后记住各日志读取位置，通过文件变化通知只读取新增字节，保留尚未完成的半行，截断或替换后重新定位。游标缓存最多保留 128 个文件，普通大段工具输出不整行保留。30 秒补查近期目录元数据。扫描范围仅为 `sessions/` 与 `archived_sessions/`，不读取认证文件。后台聊天写入的新快照也可更新额度，不必切换会话；但服务器没有写入新快照时无法得到即时额度。各窗口按实际时长从短到长分别显示剩余百分比；一个有效窗口只占一行，两个才增加第二行和所需高度。到重置时间后移除过期值，并收起对应行，等待新记录。快照原始时间保留在本机诊断状态中。

例如 Plus 同时记录 5 小时和 7 天时显示两行；Pro 或 Free 只记录一个窗口时不留第二行空位。窗口时长缺失时标注“窗口1/2”，不按套餐猜测。没有任何有效快照时只显示一行“额度 —”。紧凑布局保留两项读数，用 h、d、m 缩写窗口时长；右键隐藏“剩余额度”时统一隐藏其中所有窗口。

Free、Plus 和 Pro 共用本地 `token_count.rate_limits` 读取链路，不按套餐预设额度大小或窗口时长。支持仅有 primary、仅有 secondary、双窗口及没有额度记录的情况；缺失百分比不会当成 100%，额外 credits 余额也不会换算成订阅剩余比例。没有新快照时沿用尚未过期的账号快照，没有有效快照则显示“—”，其他会话统计仍可显示。

快照对象兼容本地记录的 `used_percent`、`window_minutes`、`resets_at` 与协议对象的 `usedPercent`、`windowDurationMins`、`resetsAt` 命名。套餐字段 `plan_type` / `planType` 原样保存在诊断快照的 `planType`，不据此拒绝未知套餐或推算额度；过期窗口移除后仍保留该信息。无效时长或重置时间只跳过对应窗口，不中断 token 统计。这里只解析已存在于本地记录中的额度对象，不启动 app-server、不新增网络查询，也不表示将其他协议通知写入日志。

主读数仍只代表普通 `codex` 额度，其他模型额度桶和额外 credits 未合并。Free/Plus/Pro 兼容回归使用生成记录，覆盖会话读取、跨会话增量读取和 HUD 额度标签；Free 与 Plus 的真实账号现场验收仍需对应机器的日志与显示结果，不能以夹具通过代替。

缓存占比为累计缓存输入除以累计输入，不是本次请求的命中率。模型、上次请求输入/输出与请求耗时来自现有日志；缺失时显示“—”，不推算价格或服务器解码耗时。

轮次按 `event_msg/task_started` 的 `turn_id` 去重，完成与中止读取相同 ID 的结束事件；工具调用、页面上下文及同轮补充输入不另起轮。缺少可识别的开始事件时显示“—”，不按用户角色消息数猜测。压缩只统计顶层 `compacted` 成功记录，优先按压缩响应 ID 去重，缺失时用窗口 ID 或记录条数；不会遍历摘要的替换历史来增加计数。它们反映本文件保留的记录，不能补回缺失或未继承的历史。

时间分别显示“用时”和“跨度”，每项独立分行放大，使用 s、m、h 或 d 缩写；请求耗时位于两项时间上方。累计运行优先使用轮次结束记录的 `duration_ms`，否则以开始/结束时间计算；尚未结束的轮次从开始计到本次读取，包含工具、模型和交互等待，结束后停住。重复轮次事件不重复相加。跨度从当前文件最早的时间记录计算到本次读取，包含两轮之间和会话停留的时间。时间戳支持日志中的 Unix 秒、毫秒与带时区日期文本；日志没有相应记录时显示缺失，不推断未保留的历史。
