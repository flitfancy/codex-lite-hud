# Codex Lite HUD

Read `README.md` and `docs/DEVELOPMENT.md` before changing the application.

- `VERSION` is the release version source. BuildInfo and file versions are generated by `scripts/build.ps1`; do not maintain a second manual version constant.
- Keep the HUD independent of network services and model calls. Codex logs, configuration and state databases are read-only; authentication files are outside the reader's scope.
- Window target selection must exclude tool, transparent and pet windows in both foreground switching and discovery. Position events remain separate from slower data and theme work.
- Use generated fixture homes for ordinary tests. Actual window metadata checks are opt-in; never move or activate the user's Codex or pet as a test.
- Put local configuration, diagnostics, test results, run copies and backups in ignored `.local/`. Release ZIPs in `dist/` use an explicit public allowlist and SHA-256.
- Run `scripts/release.ps1 -DryRun` for release validation. Keep system/client compatibility claims aligned with actual evidence. Remote publication is a separate user action.
